# 客户端模型与参数管理

## 使用步骤

在PiperX桌面终端打开客户端。

```bash
cd /home/cv/gcj/project/baseline_fast/tempo-lora
bash run_gui.sh
```

1. 在顶部“模型”下拉框选择检查点。
2. 点击“启用／切换模型”，等待权重加载和预热完成。模型卡片与事件日志显示实际握手信息。
3. 调整“推理方式”和参数。每轮开始时固定配置快照，调整在下一轮推理生效。
4. 点击“开始推理 F5”，默认只读。勾选“允许实机运动”后，每轮通过现场确认执行。
5. 按Esc停止并保持，随后可选择其他模型并点击“启用／切换模型”。
6. 点击“停止模型服务”关闭所选模型所在服务并释放模型显存。点击“模型状态”查询远端实际运行检查点与就绪状态。

“停止并保持 Esc”结束当前推理会话，相机保持开流。相机可通过“释放相机”关闭。模型服务由顶部按钮独立管理。

## 可调整参数

- 去噪次数和RTC引导强度通过逐请求采样参数传入服务端，响应中的`sampling_parameters`与日志记录实际生效值。
- 原生每块步数、TE衰减、RTC最少推进控制客户端动作调度。
- 延迟估计方式、延迟窗口、初始延迟步与延迟余量步控制RTC及相应异步推理的延迟估计。DynamicVLA使用实际时间轴丢弃过期前缀，VLASH根据估计延迟选择未来状态偏移。
- 运行秒数为0表示持续运行，回放批帧数影响录制反馈的分批方式。

完整模型默认5次去噪、RTC引导5，原LoRA默认10次去噪、引导10。实验参数与模型默认身份分别保存，模型握手和实际请求参数均可在日志核查。日志目录为`client/logs/gui`，每轮包含配置、模型metadata、预测和完成状态。

## 实现与验证

模型控制由客户端SessionWorker通过有线SSH调用`trained_model/scripts/manage_model_service.py`。管理器对白名单模型、tmux会话与精确进程身份执行检查，启动前核验模型资产，切换操作串行化，同一GPU使用单个受管模型。已有客户端连接时返回占用信息。关闭使用标准终止信号并等待进程和端口释放。

原有模型配置与采样调用保持兼容，新增采样字段在在线历史被修改前完成合法性校验。每轮请求覆盖Policy.sample_kwargs，响应回传生效参数。VLASH仍是已有TEMPO权重上的推理适配，当前权重未包含VLASH时间偏移训练增强。

客户端含GUI的82项回归通过，服务端53项回归通过。四个模型均通过客户端启用、跨模型切换、状态查询和RTC录制反馈验证，每模型3批12帧。去噪3次、RTC引导2.5均由服务端响应确认生效。活动连接下的模型切换和服务停止均被正确拒绝，断开后可以正常管理。验证最后通过客户端停止服务，两个服务端口均已释放，受管模型进程全部退出。自动验证只使用录制反馈，真实抓取效果待现场验收。
