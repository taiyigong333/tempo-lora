## 当前状态

2026-11-09已完成部署，PiperX现场GUI与4090正式8000服务已切换新版。用户要求同时支持只读和实机执行，实机运动每轮由GUI现场确认。用户选择RTC保持10次去噪，延迟超限停止。

PiperX目录为 `/home/cv/gcj/project/baseline_fast/tempo-lora`，4090目录为 `/data/gcj_data/fast/baseline/tempo`。客户端有线出口192.168.50.1，服务192.168.50.2:8000。最终模型固定formal_20261108_b16_g1/step_00010000.pt。

## 入口与参数

- 桌面Tempo LoRA · PiperX或根目录run_gui.sh打开界面，开始推理F5，停止并保持Esc。
- 当前任务目录登记“抓取旋转红色方块”，prompt为grab the rotating red square。服务端核对训练任务，其他模型任务需要按真实训练信息登记。
- 默认只读，允许实机运动需勾选且每轮弹窗确认。可选择开始前低速归位，默认归位速度10%、策略速度90%，沿用OpenPI现场参数。
- 运行秒数0为持续运行。TEMPO原生同步每块执行步数默认1，TE新预测优先衰减默认0.05，RTC最少推进默认1步，延迟余量默认1步。三种模式保持10次去噪。
- 相机由应用会话跨轮持有，持续采集并覆盖旧帧，显式释放或退出GUI时关闭。每轮CAN与模型episode重新建立。

## 客户端与服务端模块

| 端 | 模块 | 职责 |
| --- | --- | --- |
| PiperX | gui.py、settings.py | Tk界面、任务和模式参数、只读/实机每轮确认 |
| PiperX | session.py | 后台任务、资源生命周期、先预约模型连接再准备运动 |
| PiperX | cameras.py、live.py | 双RealSense常驻采集、RGB等比补黑边、30Hz实测反馈插值和连续帧上传 |
| PiperX | transport.py | 绑定有线出口、模型身份和任务/模式校验、独占推理会话预约 |
| PiperX | control.py | 原生同步、TE同一目标时刻融合、RTC绝对前缀和异步调度、独立反馈保护 |
| PiperX | robot.py | CAN状态、固件与模式确认、FK保护、六关节rad/夹爪m出口、低速归位和停止保持 |
| 4090 | serving/websocket_policy_server.py | WebSocket协议和单客户端推理预约 |
| 4090 | tempo_lora/inference.py、sam.py | episode记忆、完整连续SAM2时序、图像和实测反馈历史、任务校验、动作锚点变换 |
| 4090 | policies/policy.py、models_pytorch/pi0_pytorch.py | 归一化与多模态输入、TEMPO-MOT/ACT、64D u_t的10步flow采样和动作解码 |
| 4090 | tempo_lora/rtc.py | 解码动作空间软前缀误差到潜变量的VJP引导 |

原生同步返回动作块后执行前N步再请求下一块，保持既有闭环方式。TE按同一30Hz目标时刻对绝对关节和夹爪预测加权。RTC旧动作块换到当前state锚点、按检查点norm归一化，再通过动作解码器和flow速度对u_t反传前缀约束。当前实现为潜变量模型RTC适配。

反馈历史只由实测反馈重建，连续30Hz输入完整上传。异步结果按观测时间裁掉过期动作，剩余前缀不足、缓冲耗尽、动作来源观测超过0.5秒或控制超时均停止。启用实机运动时发送停止保持，反馈失效时请求阻尼急停。服务启动先预热原生与RTC，随后开放端口。

## 实际验证

以下为首次部署及此前阶段记录。最新连续推理结果和并行修复见本文末节及 `推理延迟故障修复.md`。

- 客户端53项、服务端28项回归通过，客户端包含真实Tk控件测试。
- 最终10000步真实GPU RTC输出float32[16,7]全有限，模型参数grad全None，峰值8.30GB。预热后3帧反馈RTC约465至476ms。
- 独立Tk GUI与合成SDK的三模式乘只读/确认执行共六种组合通过，覆盖低速归位、策略速度、取消确认、停止保持及停止后无迟到命令。相机跨轮复用和退出释放通过。
- 候选真实有线模型的三模式反馈回放通过。真实现场GUI双相机/CAN原生只读3秒完成，8批91帧反馈、7个规划目标、0运动指令，往返约234至473ms。
- 现场F5开始/Esc停止两轮通过，五轮真实只读任务共用相机进程644276。停止后空闲双图预览持续更新，最后保留原生模式和持续相机流。
- 真实现场TE在15个规划目标后、RTC在8个规划目标后因缓冲耗尽或观测过期停止。RTC第二次带引导请求完成前已触发保护。真实GPU引导路径已单独验证，现场连续异步运行未通过。
- 一次只读预测的夹爪目标超出0至0.10m，记录为保护提示，实机执行会拒绝该目标。真实运动未自动确认，现场运动指令始终为0。真实归位、执行与抓取成功率待操作者确认后评测。
- 真实桌面Xwayland截图接口不可用。独立Tk截图已检查，现场界面控件、F5/Esc和预览更新通过Tk接口核验。

## 延迟限制与实验决策

16步窗口约0.533秒，观测最大帧龄0.5秒。真实连续SAM2和反馈传输使请求积压增加，当前TE/RTC不能可靠连续运行。按用户确认保持10步与保护阈值，达到上限结束本轮并保持。

尝试只批处理SAM2图像骨干、时序记忆仍逐帧的实验未提速，BF16的8帧由约94至99ms变为104至107ms，因此最终代码撤回这一实验。正式SAM2继续原有逐帧因果实现。

## 2026-11-09 软件限位与保持使能更新

用户已明确确认以下具体数值与PiperX客户端部署范围，归位起点使用相同工作空间。

| 参数 | 此前 | 当前 |

| TCP Y范围，米 | [-1, 1] | [-1.05, 1.05] |

Z下界0、硬件关节范围和夹爪0至0.10m范围继续约束。动作帧龄和watchdog仍为0.5秒，RTC继续10次去噪和延迟超限停止。

用户确认“急停”指软件Esc/停止按钮。正常软件停止、空间超限、延迟超限及任务结束共用当前位置保持路径，关节和夹爪发送保持目标，软件不调用disable。SDK的disconnect仅回收CAN资源，固件保留位置控制及使能。保持命令发送成功后才缓存目标，并在全部保持命令完成后锁存完成标记，避免发送失败后后续停止请求被错误跳过。每轮summary.json新增robot_diagnostics，记录stop_mode及六关节使能反馈hold_joint_enabled。

CAN关节反馈失效仍使用阻尼故障急停。物理急停、控制器故障与外部失能仍由硬件处理，软件不会在检测到外部失能后自动重新使能。SDK电子急停采用阻尼模式，不能视为位置保持。依据为现场SDK源码及官方接口说明。[SDK接口](https://github.com/agilexrobotics/pyAgxArm/blob/master/pyAgxArm/protocols/can_protocol/drivers/piper/default/driver.py)

客户端59项回归通过，新增覆盖保持发送重试、夹爪发送重试、关闭时保持且无失能、反馈故障保护、外部失能拒绝自动恢复以及新软件边界。独立GUI三模式乘只读/确认执行六组合通过，确认执行和软件停止后的合成SDK六关节使能均保持True。

现场GUI已正常重载，真实双相机/CAN三轮只读任务复用相机进程646720，运动指令全部为0。首轮原生模式7批77帧、6规划目标后因观测帧龄0.505秒触发0.5秒保护，两轮F5/Esc开始和取消通过，新边界在现场config.json中核对通过。当前原生模式也可能偶发超时。相机退出任务后持续更新预览。真实机器人运动中的保持效果仍需现场确认后验证。

记录位于client/logs/hold_limits/tests.log、gui_integration.json和desktop_verification.json。此次仅修改客户端，4090模型服务沿用当前正式进程。
