# Piper-X 反馈代理数据 LoRA-TEMPO 适配

## 目标与约束

在 gh4090piper 使用 uv 部署完整 TEMPO-MOT、TEMPO-ACT、MVAE、视频均值标签和独立动作解码器。数据原件只读，Git 根目录为 `/data/gcj_data/fast/baseline/tempo`。源码放在 `tempo/`，配置和运行产物分别放在 `trained_model/config_use/` 与其余 `trained_model/` 子目录。沿用 openpi 的组织方式。

用户已确认统一指令 `grab the rotating red square`，并授权尝试完整训练流程。机器人运动仍需现场另行授权。

## 固定基线

- TEMPO 为 `dd8342a1234e7166b856ffec2d7917b51cce05e4`。
- 转换仓库分支 `piperx_to_tempo_vla` 为 `45d9f8275316c455c3aeb2c375add8b37d1bf661`。
- 初始 openpi 参考源码为 `215abfb217dbac7d5f1273282331b9b1866c0479`，该目录有历史修改，只读参考。
- 实际元信息为 393 episodes、44,398 帧、30Hz、两路 224×224 RGB。真实逐帧检查结果由运行报告记录。
- π0.5 原始权重是 JAX Orbax 格式，需要转换到独立的 PyTorch 基座目录。

## 数据流与训练范围

磁盘 action[t] 已是 state[t+1]。窗口从 action[t] 开始，各步六个关节都减同一个 state[t]，夹爪保留绝对米数。复用 DeltaActions 和 AbsoluteActions，MVAE 和独立解码器共享同一窗口构造。历史桶只读 i<t 的绝对反馈代理，不归一化，在线从 30Hz 带时间戳反馈重建。

用户后续明确要求全部轨迹用于训练，当前持久化划分包含 393 条训练轨迹，验证集合为空。所有辅助模型、策略与归一化共享这一集合，检查点选择依据训练集监测值。来源分组划分能力仍由配置支持。SAM2 按完整 episode 顺序处理每一帧，每 episode 重置。SigLIP 独立采样三帧，顺序为过去至当前。

PEFT 0.17.1 的 Linear 定向注入语言、专家注意力和 MLP，以及 SigLIP 每第四层共享注意力投影。直接包装精确路径下的线性层，以保留联合前向使用的 .weight 访问和模型层级。采用 PEFT 默认的 A 随机、B 零初始化。命中清单与可训练名单写入训练目录。

基础权重冻结，adapter 与 TEMPO 模块、u_t 投影保留 FP32。冻结主干以 BF16 计算，归一化及注意力 logits/Softmax、flow 误差与归约使用 FP32。归一化和线性层输入显式转换，修正 CUDA LayerNorm 混合类型问题。保留全 FP32 诊断。FP32 更新机制与 JAX 的数值等效尚未经验证。EMA 首版关闭。独立 MVAE 与解码器在策略训练时冻结。

## 已定位问题

- SAM2 融合原有 gate 和 out_proj 双零初始化，导致整个分支梯度恒零。保留零输出初始化，启用 LoRA 构建时令 gate=1。
- 辅助模型原有绝对动作监督与部署绝对化冲突，使用窗口起点相对化后再归一化。
- 原辅助脚本有 14D、16 帧硬编码，本项目入口从配置与数据验证后统一构建。
- 原缓存缺失回退为零。本项目完整模式在训练前检查覆盖、长度与版本，并拒绝不兼容产物。
- 原训练循环学习率可能覆盖各参数组，本项目用按组倍率的 LambdaLR。

## 验收

CPU 回归覆盖窗口偏移、历史因果性、单臂/双臂动作往返、相机掩码、注入/冻结和缓存版本。真实 GPU 验证覆盖完整前后向、FP32 梯度与 AdamW 状态、冻结权重、数步有效更新、保存重载、恢复后更新、正常服务路径和 episode 重置。实际执行结果持续写入交接及训练日志，未执行项明确保留。
