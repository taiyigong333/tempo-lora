# 安装、训练、恢复和推理

## 环境

项目根为 `/data/gcj_data/fast/baseline/tempo`。使用 Python 3.11 与 uv，依赖固定在 `tempo/uv.lock`。PyTorch 2.7.1、Transformers 4.53.2、PEFT 0.17.1。SAM2 固定提交 `2b90b9f5ceec907a1c18123530e92e794ad901a4`，采用官方 `sam2.1_hiera_tiny.pt`。

```bash
cd /data/gcj_data/fast/baseline/tempo
export PATH="$HOME/.local/bin:$PATH"
git clone https://github.com/facebookresearch/sam2.git trained_model/cache/sam2
git -C trained_model/cache/sam2 checkout 2b90b9f5ceec907a1c18123530e92e794ad901a4
mkdir -p origin_checkpoint
curl -fL https://dl.fbaipublicfiles.com/segment_anything_2/092824/sam2.1_hiera_tiny.pt \
  -o origin_checkpoint/sam2.1_hiera_tiny.pt
bash trained_model/scripts/setup.sh
```

setup 用 uv 创建独立环境，复制 TEMPO 补丁到实际导入的 Transformers 路径，并检查版本与时间注意力。SAM2 的可选掩码后处理 CUDA 扩展关闭，训练使用冻结的特征路径。

## 配置与 W&B

统一配置文件为 `trained_model/config_use/pi05_piperx_tempo_ut_lora.json`。所有路径从项目根解析。`run.sh` 默认读取它，也可传 `--config /绝对路径/config.json`。训练、统计和服务共同发现配置名 `pi05_piperx_tempo_ut_lora`。

W&B 设为 online，各辅助模型及策略建立独立 run，通过 group 关联。日志包含 loss、lr、动作重建 MSE、视频重建 MSE、梯度范数与峰值显存。断点恢复沿用保存的 W&B run id。服务器已有登录文件由运行脚本加载，API Key 只进入进程环境。也可以运行前自行导出 `WANDB_API_KEY`。

当前服务器 W&B 使用已有专用代理 `http://127.0.0.1:17890`。项目配置的 wandb.proxy 仅设置本项目进程环境，安装阶段仍使用服务器默认网络。该专用代理由服务器已有服务提供，运行前可通过 `ss -ltnp | rg 17890` 检查。默认 7890 出口曾对 api.wandb.ai 返回 403，专用出口已实际验证 API 和在线 run。

全部数据参与训练，固定 split.json 的 val_episodes 为空。训练采用 warmup 与余弦 AdamW，按配置完成轮数，best.pt 根据训练集监测值选择。策略新增参数为 FP32，冻结主干采用 BF16，flow 误差与归约、归一化、注意力 logits/Softmax 保留 FP32。配置 dtype=float32 可进行全 FP32 诊断，应使用独立产物目录。

## 从数据准备到完整训练

当前正式任务已登记为北京时间 2026-11-07 23:30，tmux 会话为 tempo_lora_2330。配置中的 training.not_before 提供提前启动保护。可读取 trained_model/runtime/schedule_20261107_2330/plan.json 和 schedule_status.json 核对计划与状态。

正式参数为 batch32、梯度累积2次、有效batch64、10000个优化器更新。每3000步保存，并在10000步结束时保存。training.cuda_allocator 使用 expandable_segments:True，已完成对应完整模型的保存恢复验证。

流水线入口负责依赖顺序、阶段日志、状态与恢复。

```bash
bash trained_model/scripts/run.sh run
```

单独执行对应命令如下。

```bash
bash trained_model/scripts/run.sh validate
bash trained_model/scripts/run.sh split
bash trained_model/scripts/run.sh convert
bash trained_model/scripts/run.sh norm
bash trained_model/scripts/run.sh sam2
bash trained_model/scripts/run.sh mvae
bash trained_model/scripts/run.sh encode
bash trained_model/scripts/run.sh decoder
bash trained_model/scripts/run.sh verify
bash trained_model/scripts/run.sh train
bash trained_model/scripts/run.sh evaluate
```

convert 使用配置指定的本地 JAX Orbax 基座，生成独立 PyTorch 权重。已有基础权重时流水线复用，单独 convert 会明确报出目标已存在。

validate 对全部 Parquet、两路视频、frame_index、episode_index、30Hz 时间戳和下一状态代理逐帧检查。sam2 根据元数据处理所有 episode/chunk，逐帧保留连续记忆，每条轨迹重置，同时生成 numpy 内存映射数组和原工具可读 npz。缓存与检查点记录契约及相关文件哈希。

norm 在每个完整窗口起点相对化六个关节，夹爪保持绝对值，并计算训练集 quantile 统计。MVAE 和独立解码器共同使用该策略归一化空间，动作维度从配置与实际数据核验为 7。MVAE 标签只取视频编码均值 mu_v。

## 恢复

```bash
bash trained_model/scripts/run.sh mvae --resume
bash trained_model/scripts/run.sh decoder --resume
bash trained_model/scripts/run.sh train --resume
# 从持久化阶段状态继续整个流程
bash trained_model/scripts/run.sh run
```

策略定期保存 3000、6000、9000 步，并在最终 10000 步保存。每次完整落盘后，原子更新 `latest.pt` 相对符号链接及 `latest.json` 元数据，`best.pt` 依据训练集监测指标选择。包含 PEFT adapter、TEMPO 新模块、u_t 投影、完整配置、基础及辅助模型哈希引用、归一化副本、优化器、调度器、全局步数、随机状态和采样位置。数据批次顺序由步数确定，恢复时校验配置与引用。若保存完成后指针更新被中断，恢复入口会发现最新的完整 step 文件并修复指针。辅助模型在 epoch 边界保存对应状态。

标准训练入口也可使用统一配置，单 GPU 一个进程。

```bash
cd tempo
uv run --no-sync scripts/compute_norm_stats.py --config-name pi05_piperx_tempo_ut_lora
uv run --no-sync scripts/train_pytorch.py pi05_piperx_tempo_ut_lora
uv run --no-sync scripts/train_pytorch.py pi05_piperx_tempo_ut_lora --resume
```

上述标准入口执行前需设置与 run.sh 一致的登录和缓存环境。规范恢复优先使用最初启动入口与配置快照。

## 服务

```bash
cd /data/gcj_data/fast/baseline/tempo
bash trained_model/scripts/run.sh serve --checkpoint /绝对路径/step_00003000.pt --port 8000
```

也可通过 `tempo/scripts/serve_policy.py` 的 checkpoint 配置进入，加载路径可为 `.pt` 或包含 best.pt 的实验目录。默认绑定 127.0.0.1，host 在配置中显式设置。

客户端发送 `episode_id`、`timestamp`、7D 绝对实测 state 与 head/left_wrist 两路 224×224 RGB uint8 图像。图像按照转换项目规则等比补黑边。每次推理允许通过 feedback 列表一次发送自上次推理以来所有 30Hz 反馈帧。

```python
result = client.infer({
    "episode_id": "trial_001",
    "feedback": [
        {"timestamp": 0.0, "state": state0,
         "images": {"head": head0, "left_wrist": wrist0}},
        {"timestamp": 1 / 30, "state": state1,
         "images": {"head": head1, "left_wrist": wrist1}},
    ],
})
actions = result["actions"]  # float32[16, 7]，六关节 rad 与夹爪绝对开口 m
```

历史分支将实测 state[t] 放入 action[t-1] 槽位，按离线相同的桶边界汇总。首次输入有启动 padding。episode_id 改变或 reset=True 会统一重置历史图像、动作与 SAM2 状态。输入时间戳间隔必须保持 30Hz，容差 2ms。

策略预测 16 步，配置的 execute_steps 表示闭环每次推进长度。真实机器人控制应先确认关节位置接口、单位、限位、跟踪延迟及现场执行授权。此服务返回动作块，机器人驱动由控制系统对接。

## 验证与诊断

```bash
cd tempo
JAX_PLATFORMS=cpu uv run --no-sync pytest tests/test_tempo_lora.py -q
cd ..
bash trained_model/scripts/run.sh verify
```

基础回归覆盖 7D/14D 动作往返、下一状态偏移、缺失相机 mask、历史因果性与 episode 重置、PEFT 初始化与冻结、FP32 AdamW、缓存契约拒绝、精确恢复采样、旧配置与新配置发现。完整 verify 使用真实训练 batch，检查数步梯度更新、冻结权重全量摘要、重载输出、恢复后的下一次更新及标准服务加载路径。

evaluation.json 报告离线反馈代理动作误差及策略延迟，包含 data_split。真机闭环成功率另行实测。项目当前实际执行结果见交接文档和 runtime/status.json。
