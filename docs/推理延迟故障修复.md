# 推理延迟故障修复

## 结果与使用

2026-11-09已修复时间集成连续推理的积压故障及CAN反馈缓存竞争。正式服务为192.168.50.2:8000，现场客户端保持时间集成TE和只读选择，F5开始，Esc停止保持。相机继续跨轮开流。真实运动每轮由操作者在GUI确认。

当前最终10000步模型继续10次去噪，动作最大帧龄0.5秒、CAN反馈最大帧龄0.1秒及已确认的空间保护继续生效。RTC仍会触发时效保护，不能宣称持续RTC运行通过。

## 失败证据

最新三次用户现场确认执行的TE会话均只收到首块预测，在8个规划目标后报异步缓冲耗尽或观测过期。前一次原生实机执行7批75帧，在0.503秒帧龄处停止。这四次日志的hold_joint_enabled均为六个True，停止方式为position_hold_keep_enabled。

原生请求由约228ms随反馈积压升至473ms，批次由1帧增至15帧。SAM2逐帧处理与后续视觉/策略串行，TE第二次预测完成前，旧块已到0.5秒时效上限。此处失败记录没有空间限位错误。

长时真实只读测试还发现CAN反馈陈旧或时钟异常。总线累计错误、丢包和bus-off均为0。SDK的关节getter返回共享可变缓存，保护与采样线程均会更新它。原采样在robot锁外读取缓存，并先取当前时刻再取对象时间戳，存在新反馈被误判为未来时间的竞争。旧日志缺少实际帧龄，无法单凭该条日志区分未来时间与真实过期，新增日志已补充通道和帧龄。

## 实现与依赖

- SAM2完整连续帧处理位于独立线程与CUDA流，两路SigLIP视觉编码同时排入主流。head融合前等待当前批SAM2完成事件，再运行VLM前缀和去噪。每批仍处理全部反馈帧。
- SAM2特征保持GPU Tensor，避免逐帧CPU往返。推理错误时同样排空SAM2任务，下一episode重置时不会与旧批次记忆写入竞争。
- 局部编译去噪、动作解码器、SAM2图像骨干与记忆编码。时序记忆选择、反馈历史、任务和动作语义沿用现有实现。未采用无实际收益的注意力内核替换或SigLIP单独编译。
- 推理冻结参数仍允许RTC对输入潜变量计算VJP。服务在开放端口前预热原生和RTC两条路径，首次编译与缓存位于trained_model/cache/inductor_inference。
- client的CAN采样在robot锁内读取并复制反馈，先快照时间戳，再读取当前时刻。关节、姿态、夹爪和控制器状态读取使用相同顺序，真实过期与未来反馈仍按原阈值拒绝。

部署选项为trained_model/config_use/pi05_piperx_tempo_ut_lora.json中的inference.compile_inference=true、parallel_sam=true。create_policy和OnlinePolicy的新增选项默认False，既有调用保持原路径。部署选项在读取检查点训练配置前保存，服务握手包含denoise_steps、compile_inference和parallel_sam。

主要修改为tempo_lora/inference.py、sam.py、models_pytorch/pi0_pytorch.py和客户端live.py、robot.py。client的predictions.jsonl新增feedback_ingest_ms与policy_timing，便于区分反馈接入和策略耗时。并行模式中policy_timing包含融合等待。

## 数值差异

局部编译与执行路径变化不保证浮点逐位一致。最终完整组合以同一检查点、固定反馈和噪声完成8个原生/RTC对照，全部输出有限、模型参数grad为None。原路径重复执行误差为0，最终路径最大关节绝对误差约0.02430rad，最大夹爪误差约0.001592m。逐维结果见trained_model/runtime/latency_fix/final_runtime_numeric.json。这是固定输入数值检查，不能作为抓取成功率或实机误差结论。
